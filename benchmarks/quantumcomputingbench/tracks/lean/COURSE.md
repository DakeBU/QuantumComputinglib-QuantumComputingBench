# Graph-grounded Lean course

This experimental course develops quantum-computing proof assessment by
mathematical prerequisites and mechanisms. It preserves the shared core IDs,
contracts, families and splits. Knowledge, Lean syntax and mixed views of the
same target remain one question. The non-Lean track and frozen releases remain
independent of this sidecar's qualification.

The cumulative plan is [course-v3.json](curriculum/course-v3.json): 18 distinct
existing cores. The preserved [first plan](curriculum/course-v1.json) and
[second plan](curriculum/course-v2.json) retain their nine-core and 13-core
scopes and original execution evidence. New companions require content-bound
semantic review and actual authored reference receipts before the corresponding
CLI audit or export succeeds. A candidate file, graph node or difficulty label
alone cannot enable evaluation gold.

## Difficulty is conditional

| Layer | Construction assessment | Examples in this slice |
| --- | --- | --- |
| D0 | Knowledge of assumptions, objects and conventions, assessed using the same core's canonical semantic rubric | Distinguish row Gram from column isometry, joint mass from a marginal, finite-width rank from a circuit bound |
| D1 | Precise statement reading and a disclosed library application | SP009 real-to-complex isometry calibration |
| D2 | Local symbolic construction and entry/sum reasoning | Normalization/readout domains, finite sums, permutation chronology, concrete clean/dirty work, shifted jets |
| D3 | Joining mathematical interfaces and preserving every AND premise | BE109 tensor lift, BE112 LCU composition, SP113 anchored mass and counterexample, SP114 rank, LA102 determinant |
| D4 | Parametric induction and global invariant/representation or degree control | SP007 transfer induction, SP008 joint probability, SP120 cutoff ledger, SP104 endpoint multiplicity and degree |

D0 facets do not create extra questions. D1--D4 are provisional mathematical
assessments of the inspected construction routes, not measured model difficulty.
An imported exact-root theorem can turn a D3 construction into a D1 application.
Controls and callable shortcuts are disclosed, not hidden to inflate difficulty.
Actual model calibration needs fixed model/exposure/tool profiles and measured
outcomes. Tactic count, source lines, graph distance and node count do not define
these bands.

## Versioned scope

Version 3 adds BE110, BE111, BE102, SP101 and SP104. The cumulative split is
nine train, four dev and five public-test cores. Bands contain D1: one, D2: eight,
D3: five and D4: four. All earlier 13 entry objects, core contracts and splits
are retained.

BE110 states the exact same-selector inverse and both composites before
permutation unitarity. Different selector labels can happen to name the same
permutation; using another label is not guaranteed to invert the selected map,
rather than always failing. BE111 fixes the contracted row at the inverse image
and proves the matrix and column-vector chronology explicitly.

SP101 checks shifted coefficients, ordinary derivative realization and an upper
degree bound for arbitrary finite jet data. SP104 concerns arbitrary polynomials
`p,q`, not only the source interpolant. Its reusable general-point
jet/divisibility equivalence feeds independent endpoint branches; coprimality
joins them before the degree contradiction. This is an actual reconvergent
pattern in the supplied obligation graph, not a claimed extraction of the
elaborated Lean proof-term graph. The explicit references use the provider in
both branches.

BE102 checks the literal finite seven-wire map: clean-input arithmetic and
zero work, all-input row and entering-work preservation, and two dirty-input
witnesses. One dirty example still has the correct address; the other does not.
Neither returns dirty work to zero. This is not an arbitrary-width adder, a cost
theorem or an arbitrary-quantum-input no-entanglement claim. Kernel finite
decision is a valid disclosed shortcut, so the construction band is D2, not
proof-synthesis depth inferred from the enumerated cases.

The named source clean-action theorem and some corollaries carry additional
`native_decide` axioms outside this benchmark's fixed policy. They were excluded
from approved retrieval. The authored root uses kernel decision/finite bit
cases with the unchanged three-axiom whitelist. This does not refute the source
theorem or establish a whole-module trust audit.

Thirteen declaration-only interfaces were checked by actual signature
ascriptions and admitted to scoped retrieval. `closed_book` disables retrieval,
while full imports and known shortcuts remain callable; this is not an import
firewall. Mathematical construction, library application and finite-decision
bypasses must be reported separately.

Version 2 adds BE106, BE112, SP113 and SP120 without replacing any earlier
question, view, contract or split. It contains five train, four dev and four
public-test cores. Construction bands contain D1: one, D2: four, D3: five and
D4: three. Public-test exercises remain publicly exposed, not a hidden holdout.

BE106 separates unconditional trigonometric unitarity from exact amplitude
readout on `[-1,1]`, allowing precisely the angle extension stated by the current
canonical question. BE112 joins tensor, block and permutation certificates, then
distinguishes arbitrary unitary replacements from uniqueness under a full
inverse equation. Its projected-block and cleanup counterexamples remain prose,
not extra kernel-checked claims.

SP113 follows the actual central grid point through a unit sample, squared-mass
lower bound and positive normalizer; a separate positive `Fin 2` vector has mass
less than one. This witness is not another Hermite sample table. The source uses
`n+1` qubits, so `n=0` still means two samples. SP120 maintains the actual cutoff
interval and separately proves exact search and initialized-producer counters.
Its field/comparison ledger is not finite-bit, runtime or quantum circuit cost.
The source answer's phrase "already-decided low-order index" is interpreted as
the current natural-index start; recursion processes descending powers of two.

Every new formal root has independent source-blind reconstruction and a distinct
source-aware comparison. All four comparisons explicitly mark whole-question
coverage partial: formal conclusions do not certify prescribed proof methods,
explanatory prose or the omitted physical claims. In particular, a conjunction
about an anchored mass does not certify that a proof avoided using positivity.

### Preserved first expansion

The original four experimental roots remain unchanged. Five companions add

The course therefore plans nine distinct existing cores, not nine new
mathematical targets or canonical admissions. SP005/LA102 use their existing

BE105 includes both directions of the unitary-normalization equivalence. The
existing library's sufficient-condition theorem alone does not supply its
necessary direction. SP114 requests the explicit shifted-Taylor identity,
factorization through `Fin (d+1)` and rank bound together; degree controls a
width upper bound, not rank equality or minimal width. Finite-column typing and
the arbitrary-row generalization are disclosed. All prose, requested proof
methods and physical/resource interpretations require separate assessment.

An accepted obligation establishes a scoped formal claim under its fixed imports
and hypotheses. It is not automatically a useful search action, a faithful NL
explanation or a calibrated process reward. Root correctness, prose coverage and
search usefulness remain separate labels. A mathematical counterexample, such
as SP113's positive vector, is also distinct from a deliberately ill-typed proof
used to check verifier rejection.

Source statements/definitions, semantic reconstruction and actual kernel checks
remain separate. The normalized ambient interfaces added after the first blind
decode are explicitly labelled; earlier local packets and probe failures are
preserved. No new source-module audit, finite-bit compiler or circuit-resource
certificate is inferred from these exercise roots.

## Graphs and curriculum edges

`topology` describes the evaluator-supplied AND-obligation graph. It does not
claim to extract Lean proof-term dependencies or measure semantic reasoning
depth. The snapshot also contains module imports/ownership, conceptual and
planned relations, with their own evidence boundaries. They are not silently
converted into theorem implications.

Single roots, chains, AND joins and reused interfaces are explicit. A transitive
reuse triangle is not labelled a genuine diamond: that requires incomparable
branches with a shared ancestor and later reconvergence. Missing shapes remain
in the next-batch frontier; nodes are not padded to manufacture coverage.

Course prerequisites are recommended pedagogical edges, not extra theorem
hypotheses or claims of actual proof dependence. They cannot run from a later
evaluation split into training. Export ordering respects prerequisites, including
same-band prerequisites; filtered stages list omitted prerequisites without
injecting their answers. Existing splits are never silently reassigned.

Coverage reports count exact task anchors and their source files in the frozen
snapshot. Its full declaration inventory is an audit denominator, not an estimate
of how many valid or reviewed questions can be generated. Task review does not
clear an entire legacy node/module's source-semantic audit debt. Withheld and
planned nodes remain outside current gold.

reference qualification:

```sh

  --split train --output _out/lean-course-train.json

  --band D3 --output _out/lean-course-D3.json
python benchmarks/quantumcomputingbench/scripts/lean_course_v3.py run-fixture \
  --view qcb-course-sp-104-v1 --episode-dir ../qcb-eval-private/sp104-course-fixture-fresh
```

Use `lean_course.py` and `lean_course_v2.py` for the preserved nine-core and
13-core versions. Version 3 adds five companions; its reference command checks
only that new cohort. It additionally requires the sanitized source-alignment
supplement for the unchanged version-2 roots, without relabelling their old
Lean receipts as new replays.

Historical version-2 behavior: The successor CLI
validates all historical qualifications as well as its new cohort; its
`check-references` command replays only the four newly added companions.

Exports contain fixed questions/targets and answer-free protocol state. They
omit reference proofs, controls, negative proofs, source comparison verdicts
and grading answers. References remain public elsewhere; this is not a blind
test. The fixture command uses a simulation verifier and measures no Lean or
model performance.
